# Co-op Billing / Cost Sharing with Wholesaler

## Description

MerchTank allows users to designate specific line items as "co-op" items where the cost is split between BBC and the wholesaler. During checkout, users can specify which items are co-op and what percentage/dollar amount the wholesaler should cover. The wholesaler is then invoiced for their portion separately. This feature is critical to BBC's relationship with distributors and affects budget management, order processing, and financial reconciliation.

## Current Implementation

**User Workflow:**
- During checkout, users can mark specific line items (or the entire order) as co-op
- For co-op items, user specifies: wholesaler entity, dollar amount to be covered by wholesaler
- Checkout calculates: BBC pays (Total - Wholesaler Amount), Wholesaler pays (specified amount)
- Order confirmation shows billing split
- Separate invoices generated for BBC and Wholesaler portions

**Business Rules:**
- Co-op agreements are pre-established (not negotiated per-order)
- Splitting is at the line-item level (different items can have different co-op arrangements)
- Wholesaler amounts are specified in dollars (or as percentage if that exists)
- Co-op orders require additional approval (from wholesaler? from finance?)
- Financial reconciliation must account for split billing

**Current Technical Implementation:**
- Co-op checkbox/toggle on cart items
- Wholesaler selector dropdown during checkout
- Dollar amount entry field
- Order record captures co-op designation and amounts

**Systems Involved:**
- MerchTank cart/checkout, order management, invoicing system (Rootstock ERP)

## Target Implementation

Salesforce B2B Commerce has no native co-op billing concept. This must be built as a custom checkout extension.

**Proposed Salesforce Architecture:**

1. **Custom Objects:**
   - `Co_op_Agreement__c`: Master record for pre-established co-op relationships
     - Fields: Account__c (wholesaler), Brand__c, Co_op_Percentage__c OR Co_op_Fixed_Amount__c, Active__c, Start_Date__c, End_Date__c, Approval_Required__c
   - `Order_Co_op_Detail__c`: Line-level co-op split (master-detail to Order or OrderItemSummary)
     - Fields: Wholesaler__c, BBC_Amount__c, Wholesaler_Amount__c, Co_op_Type__c (Percentage, Fixed Amount), Approval_Status__c

2. **Checkout Flow Customization:**
   - Custom LWC checkout step: "Co-op Billing"
     - Display co-op-eligible line items
     - Allow marking items as co-op
     - Selector for wholesaler
     - Input for co-op amount (with smart defaults from Co_op_Agreement__c)
     - Preview of split amounts (BBC amount + Wholesaler amount = Total)
   - Apex Cart Calculate API extension to handle co-op pricing/tax calculations
   - Custom validation to ensure co-op amounts don't exceed item total

3. **Order Data Model:**
   - Custom fields on OrderItemSummary or new OrderCoopDetail__c object:
     - Is_Coop_Item__c, Coop_Wholesaler__c, BBC_Amount__c, Wholesaler_Amount__c, Coop_Approval_Status__c

4. **Approval Workflow:**
   - If co-op order requires approval: custom Approval Process or Flow
   - Route to wholesaler or finance for authorization
   - Can be based on amount threshold or all co-op orders

5. **Invoice Generation Integration:**
   - Platform Event triggered when co-op order ships
   - Rootstock ERP subscriber creates two invoices: one for BBC, one for wholesaler
   - Data passed: order number, line items, BBC amount, wholesaler amount, wholesaler entity

## Gaps & Risks

**Gap CB-G1: No Native Co-op Billing Concept**
- Severity: Critical
- Description: B2B Commerce doesn't support cost-sharing or split billing
- Impact: Co-op arrangements affect both revenue recognition and customer relationships
- Resolution: Custom checkout component + Order data model extensions
- Effort: L (2-3 weeks)

**Gap CB-G2: Co-op Approval Workflow**
- Severity: High
- Description: Unclear if co-op orders require additional approval (from wholesaler or finance)
- Impact: If approval is required, checkout must route to approval process before order can be placed
- Resolution: Confirm with BBC; implement Approval Process if needed
- Effort: M (if approval required)

**Gap CB-G3: Integration with Rootstock ERP**
- Severity: High
- Description: Invoices are generated by Rootstock, not in Salesforce
- Impact: Co-op split amounts must flow from Salesforce to Rootstock for correct invoicing
- Resolution: Use Platform Events to notify Rootstock of co-op orders; Rootstock generates split invoices
- Effort: M (integration dependency)

**Gap CB-G4: Financial Reconciliation**
- Severity: High
- Description: Finance team must reconcile split billing with actual payments from wholesalers
- Impact: Unclear how co-op amounts are tracked and matched to actual wholesaler payments
- Resolution: Design reporting layer to show co-op amounts by wholesaler, payment status
- Effort: M (reporting + potential custom objects for payment tracking)

**Gap CB-G5: Co-op Agreement Management**
- Severity: Medium
- Description: Pre-established agreements must be maintained and applied consistently
- Impact: Incorrect co-op amounts could result in revenue leakage
- Resolution: Build Co_op_Agreement__c configuration with validation rules
- Effort: Bundled with CB-G1

## Open Questions

1. Are ALL co-op agreements pre-established, or can they be negotiated per-order?
2. What triggers the approval workflow for co-op orders? All orders, or only above a certain amount?
3. Is co-op percentage or fixed dollar amount? Or both?
4. How is the BBC portion funded? From the user's brand budget, or from a separate co-op budget?
5. Can co-op arrangements vary by brand? By product category?
6. What is the process for reconciling actual wholesaler payments to co-op invoices?
7. Are there any restrictions on which wholesalers can be co-op partners?
